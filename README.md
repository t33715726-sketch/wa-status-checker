# מי לא רואה את הסטטוס שלי?

כלי שמזהה אנשים שמתכתבים איתך בוואטסאפ ו**אינם שמורים אצלך ביומן הטלפון** — ולכן
לא רואים את הסטטוס שלך — ומייצר קובץ אנשי קשר אחד שמוסיף את כולם בבת אחת.

---

## למה זה עובד

פרטיות הסטטוס בוואטסאפ מוגדרת כברירת מחדל ל"אנשי הקשר שלי". המשמעות:
הסטטוס מוצג רק למי ש**אתה** שמרת ביומן, לא למי ששמר אותך. כל אדם שמנהל איתך
שיחה אישית ואינו שמור אצלך הוא בדיוק הפער.

### שני מקורות, ולכל אחד תפקיד אחר

**וואטסאפ עונה רק על "עם מי יש לי קשר":**

| מקור | מה זה אומר |
|---|---|
| קיימת שיחה אישית | הוא מכיר אותך → ודאות גבוהה |
| הוא שלח לך הודעה | ודאות מקסימלית → מסומן "כתב לך" |
| `contact.notify` קיים | וואטסאפ מכיר אותו, בדרך כלל מקבוצה משותפת → ודאות נמוכה |

**שירות זיהוי מספרים (Me) עונה על "מי שמר אותי":** התשובה המלאה, כולל אנשים
שמעולם לא כתבו לך. המסלול בנוי ומוכן ב-`src/providers/meProvider.js`, אבל
**כבוי כברירת מחדל** — הוא דורש גישה מורשית לספק. ראה `docs/DECISIONS.md`.

**ספר הטלפונים שלך עונה על "את מי כבר שמרתי":** המשתמש מעלה ייצוא של אנשי
הקשר שלו (vCard או CSV), הקובץ נקרא **בדפדפן בלבד**, וכל מי שנמצא בו יורד
מהרשימה ומהקובץ.

> **אסור לשאול את וואטסאפ מי שמור אצל המשתמש.** השדה `contact.name` אמור
> להחזיק את השם מיומן הטלפון, אבל וואטסאפ לא מעבירה אותו בסנכרון הזה. גרסה 1
> הסתמכה עליו, קיבלה רשימת "שמורים" ריקה, סיווגה את **כולם** כלא-שמורים —
> והייבוא דרס שמות של אנשי קשר קיימים. מקור האמת היחיד הוא ספר הטלפונים
> של המשתמש עצמו.

התוצאה מחולקת ללשוניות: **שמרו אותך** (מ-Me), **מתכתבים איתך** (ודאות גבוהה)
ו**מקבוצות משותפות** (מוכר לוואטסאפ, בלי שיחה — ודאות נמוכה). אפשר להריץ את
שני המקורות באותו ביקור; הם מתמזגים לרשימה אחת ולקובץ אחד, בלי כפילויות.

**שכבת הביטחון חלה על שני המקורות.** Me יודע מי שמר *אותך*, הוא לא יודע את מי
*אתה* שמרת — ולכן גם התוצאות שלו עוברות הצלבה מול ספר הטלפונים לפני שהן
מגיעות לקובץ.

## אבטחה ופרטיות — מה נבנה בפועל

| נושא | מימוש |
|---|---|
| פרטי התחברות (creds ומפתחות Signal) | **בזיכרון בלבד.** `src/memoryAuthState.js` — לא נכתבים לדיסק, לא למסד נתונים |
| אחרי סיום הסריקה | `sock.logout()` — **המכשיר המקושר מבוטל אוטומטית** בצד וואטסאפ |
| מחיקת מפתחות | דריסה אקטיבית של האובייקט (`wipe()`), לא רק שחרור הפניה |
| ספר הטלפונים של המשתמש | נקרא ב-`public/contacts.js` **בדפדפן בלבד** — לא נשלח לשרת, לא נשמר |
| מספרי טלפון בשרת | משוחררים מיד עם שליחת התוצאה. אין נקודת קצה לייצוא |
| בניית קובץ ה-vcf | בדפדפן, אחרי בדיקה חוזרת של כל מספר מול ספר הטלפונים |
| לוגים | `pino` עם redact על טלפון/JID/שם + חוק ברזל: לא כותבים מזהים |
| מחזור חיים | מחיקה אחרי 10 דק' חוסר פעילות, תקרה קשיחה 20 דק' |
| ריסטארט של השרת | מוחק את כל הסשנים — אין התמדה בכוונה |
| הזרקה ל-vCard | בריחת `\ ; , CRLF` לפי RFC 6350 + בדיקה אוטומטית |
| CSP | `default-src 'self'` בלי `unsafe-inline` — אין סקריפט או סגנון מוטבע |
| הגבלות | 2 סשנים ל-IP, 40 סשנים במקביל, rate limit על ה-API |
| הרשאות | קונטיינר רץ כ-`node`, לא כ-root |
| הודעות | לא נקראות ולא נשלחות. `markOnlineOnConnect: false` — הנוכחות שלך לא משתנה |

**מה לא מובטח:** חיבור כמכשיר מקושר הוא שימוש לא רשמי בוואטסאפ. שימוש בהיקף
גדול או מכתובת IP אחת עלול להוביל לחסימה מצד Meta. זה סיכון של המוצר, לא של הקוד.

## פריסה ל-Railway — צעד אחר צעד

### 1. העלאה ל-GitHub

```bash
git init
git add .
git commit -m "מי לא רואה את הסטטוס שלי"
git branch -M main
git remote add origin https://github.com/<שם-המשתמש>/<שם-הריפו>.git
git push -u origin main
```

### 2. יצירת השירות ב-Railway

1. היכנס ל-**railway.app** והתחבר עם GitHub.
2. לחץ **New Project** → **Deploy from GitHub repo**.
3. בחר את הריפו שהעלית. אשר ל-Railway גישה אם הוא מבקש.
4. Railway יזהה את ה-`Dockerfile` לבד ויתחיל לבנות. חכה ל-**Success**.

### 3. משתני סביבה

בתוך השירות → לשונית **Variables** → **New Variable**, והוסף:

| Name | Value |
|---|---|
| `NODE_ENV` | `production` |
| `TRUST_PROXY` | `1` |
| `MAX_CONCURRENT_SESSIONS` | `40` |
| `LOG_LEVEL` | `info` |

את `PORT` **לא** מגדירים — Railway מזריק אותו לבד.

### 4. כתובת ציבורית

1. לשונית **Settings** → אזור **Networking** → **Generate Domain**.
2. בחר פורט `8080` אם הוא שואל.
3. פתח את הכתובת שנוצרה. אמור לעלות המסך הראשי.

### 5. דומיין משלך (אופציונלי)

ב-**Settings → Networking → Custom Domain**, הוסף את הדומיין, ואצל רשם הדומיין
צור רשומת `CNAME` לכתובת ש-Railway נותן. ה-SSL נוצר אוטומטית.

### 6. בדיקה אחרי עלייה

```bash
curl https://<הדומיין-שלך>/healthz     # {"ok":true,...}
```

ואז בדפדפן: לחיצה על "סריקת קוד QR" → קוד אמור להופיע תוך 2-5 שניות.

## משאבים ועלות

| פרמטר | ערך |
|---|---|
| זיכרון לסשן פעיל | ~40-90MB (תלוי בכמות אנשי הקשר) |
| מגבלת heap | 512MB (`NODE_OPTIONS` ב-Dockerfile) |
| סשנים מקבילים מומלץ | 40 על 1GB RAM |

אם מגיעים לעומס: להעלות את ה-RAM בשירות ולעדכן `MAX_CONCURRENT_SESSIONS`
ואת `--max-old-space-size` בהתאם. מעבר ל-replica אחד דורש
sticky sessions — הסשן חי בזיכרון של תהליך ספציפי.

## סטטיסטיקה אנונימית (אופציונלי)

כבוי כברירת מחדל. אם מפעילים, נשלחות **ספירות בלבד** — בלי מספרים, בלי שמות, בלי IP.

טבלה ב-Supabase:

```sql
create table public.scan_events (
  id bigint generated always as identity primary key,
  saved_contacts int not null default 0,
  known_contacts int not null default 0,
  chats          int not null default 0,
  chat_gap       int not null default 0,
  group_gap      int not null default 0,
  total_gap      int not null default 0,
  created_at timestamptz not null default now()
);

alter table public.scan_events enable row level security;
-- בלי policies: רק service_role כותב. anon ו-authenticated חסומים לגמרי.
```

ואז ב-Railway: `STATS_ENABLED=true`, `SUPABASE_URL=...`,
`SUPABASE_SERVICE_ROLE_KEY=...`.

> מפתח ה-service role הוא סוד. רק במשתני סביבה בשרת, לעולם לא בקוד ולא בדפדפן.

## מגבלה מוצרית שכדאי להכיר

דפדפן לא יכול לכתוב ליומן אנשי הקשר של הטלפון. לכן "הוספה בבת אחת" מתבצעת
דרך קובץ `.vcf` שהמשתמש פותח בטלפון ומייבא בלחיצה. התחילית בשם (ברירת מחדל:
"סטטוס") מאפשרת לו לאתר ולמחוק את כולם בקלות בהמשך.

ייבוא vCard ממזג לפי מספר טלפון ו**דורס** את השם של איש קשר קיים. לכן הקובץ
נבנה בדפדפן, וכל מספר נבדק מול ספר הטלפונים פעמיים — פעם בסינון הרשימה ופעם
שנייה ב-`buildVcf()` ממש לפני הכתיבה. מספר שכבר שמור אינו יכול להגיע לקובץ,
ולכן הייבוא אינו יכול לשנות איש קשר קיים.

> אם בכל זאת קרה משהו לא צפוי אחרי ייבוא: contacts.google.com ← גלגל השיניים ←
> **ביטול שינויים** מחזיר את ספר הטלפונים אחורה עד 30 יום.
